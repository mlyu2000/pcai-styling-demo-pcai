PCAI Styling Demo — Process Flow

who calls whom, in what order · the 6-step IDD flow on PCAI (on-prem) · request-scoped per-role provider routing · every model call has a declared fallback

Two entry points

  • • Browser SPA → the 6-step Styling Workflow tab (step-by-step, human gate between sketch and combine)
  • • OpenClaw agent → same /api/flow/*, stdlib client, pcai|gemini|both, writes run_summary.json
  • • Both hit the exact same backend contract — the UI is a client of the agent API, not a separate path

The 3 model roles

  • • brain (vision LLM) → LiteLLM /v1/chat/completions — describes references, detects body color
  • • image → /v1/images/edits — the 4 image steps (sketch/combine/view/recolor)
  • • i2v → /v1/videos create → poll → /content — the only async, long step

Routing rule (v43+)

  • • Per-role ContextVar set once per request; resolvers pick external vs on-prem independently
  • • is_external on the image role gates the sdcpp prompt-embed (external OpenAI servers reject it)
  • • Keys are request-scoped — never written to disk or a secret
