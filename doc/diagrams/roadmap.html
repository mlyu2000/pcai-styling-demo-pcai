PCAI Styling Demo — Production Path

From validated PoC (v45/v23) to production-grade service · 4 phases · current demo deliberately keeps deterministic fallbacks + scale-to-0 for responsiveness

Why this order

  • • Harden → scale → fidelity: each phase multiplies the last
  • • The per-role provider design (v43+) is what keeps model upgrades cheap
  • • Every phase ships on the existing Helm chart — no re-architecture
  • • Demo fallbacks (Phase 0) become SLO-backed behavior (Phase 1)

Decisions needed (ADM)

  • • GPU budget: concurrent-stylist target (N GPUs) → 80GB ask
  • • Multi-view fidelity: accept approximation vs fund the model
  • • Auth model: AD/OIDC integration for the styling team
  • • Template ownership: per-stylist vs shared library + RBAC

Already production-safe

  • • Zero hardcoded URLs — fully platform-adaptive (values.yaml)
  • • Secrets in K8s only; external keys request-scoped (never stored)
  • • Durable state on NFS (results, templates, weights)
  • • Deterministic fallbacks with declared mode = honest degradation
